Workflow Architecture — Competitive Analysis

Deep comparison of n8n, LangGraph, Flowise, Dify, and CrewAI against Devgentic's current workflow system.
Goal: Identify what we need to build a robust, highly adaptable, private-first workflow engine.

1. Platform Overview

n8
n8n
General-purpose workflow automation with 1000+ integrations. AI via LangChain cluster nodes. Stack-based sequential engine. Self-hosted or cloud.
LG
LangGraph
Code-first cyclic graph engine for agent runtimes. Explicit loop support, checkpointing, state machines. Python/JS SDK. Most architecturally expressive.
Fw
Flowise
Low-code LangChain visual builder. Chatflow (DAG) + AgentFlow (cyclic). Deep RAG pipeline support. AI-first, limited non-AI automation.
Df
Dify
Visual LLM app builder with typed nodes (LLM, Code, IF/ELSE, Iteration, HTTP). Chatflow vs Workflow modes. Plugin architecture. MCP support.
Cr
CrewAI
Multi-agent role-playing framework. Agent/Task/Crew model. Sequential + Hierarchical processes. Flows for deterministic orchestration. 4-type memory.
Dg
Devgentic (Current)
Native macOS visual DAG builder. Bot + Agent nodes. Sequential topological execution. Context forwarding with truncation. 4 agent architectures per node.

7. Gap Analysis — What We Need to Build

Prioritized by impact on user expressiveness. Items marked NEED are missing entirely. Items marked UPGRADE exist but are insufficient.

P0 — Critical (Unlocks fundamentally new workflow patterns)

1
Condition / Router Node
An IF/ELSE node that evaluates upstream output and routes to one of N branches. Two variants: rule-based (string contains, regex match, value comparison) and LLM-based (classifier prompt picks a branch). This is the single highest-impact addition — every competitor has it. Without it, all paths always execute, making workflows wasteful and unable to express any decision logic.
Reference: n8n IF/Switch, Dify IF/ELIF/ELSE, LangGraph conditional_edges, Flowise Condition Agent
2
Loop / Iteration Node
Allow controlled cycles with a max-iteration cap and exit condition. Two forms: Retry loop (generator → evaluator → loop back or exit) and Collection iterator (process each item in an array). The cycle detection should allow backward edges only through a Loop node which enforces the iteration cap. This enables iterative refinement, the Review & Critique pattern, and batch processing.
Reference: LangGraph native cycles, Dify Iteration/Loop nodes, Flowise Loop node, n8n Loop Over Items
3
Parallel Branch Execution
When independent branches exist in the DAG (no data dependencies between them), execute them concurrently via TaskGroup. The topological sort already identifies independent "levels" — nodes at the same level with no mutual edges can run in parallel. Fan-in merges wait for all branches. This is pure execution engine work — no UI changes needed.
Reference: LangGraph superstep, Dify parallel branches (up to 10), n8n planned but not shipped

P1 — High (Significantly expands what users can build)

4
Human-in-the-Loop Gate Node
A dedicated workflow node that pauses execution and presents intermediate results to the user for review. The user can approve (continue), reject (stop), or edit (modify the data before continuing). Uses ExecutionSuspensionService (already exists for per-tool HITL) but at the workflow orchestration level. Critical for high-stakes workflows.
Reference: Dify Human Input node, Flowise Human Input node, LangGraph interrupt(), n8n Wait node
5
Code / Transform Node
A lightweight non-LLM node that executes a user-defined transformation: regex extraction, JSON path queries, string formatting, data reshaping. Runs instantly with zero token cost. Since this is a sandboxed macOS app, options include: embedded JavaScriptCore, a restricted Swift expression evaluator, or Lua. This prevents burning LLM tokens on deterministic operations.
Reference: n8n Code node (JS/Python), Dify Code node (Python/JS), Dify Template (Jinja2), Flowise Custom Function
6
Structured Data Model (Replace Text Truncation)
Replace the current text-based context forwarding (2K/node, 6K total) with a structured envelope: { text: String, json: [String: Any]?, artifacts: [MediaArtifact], metadata: NodeExecutionMetadata }. Downstream nodes should be able to reference specific upstream fields, not just receive a truncated text blob. This is foundational for multi-port and transform nodes.
Reference: n8n items {json, binary}, LangGraph typed state with reducers, Dify variable selectors

P2 — Medium (Polish and power-user features)

7
Sub-Workflow / Nested Workflow Node
Allow workflow profiles to be added as nodes inside other workflows. The inner workflow executes as a black box — receives input, runs its DAG, returns terminal output. Requires recursion depth limit (e.g., max 3 levels). Enables modular, reusable workflow blocks.
Reference: n8n Execute Sub-workflow, Dify Workflow-as-Tool, Flowise Execute Flow, LangGraph Subgraphs
8
Error Handling Upgrade
Currently: failed nodes are skipped and dependents are skipped. Need: per-node retry count, error output branch (route to alternative path on failure), and optional continue-on-error flag. Error branch enables graceful degradation instead of cascade failure.
Reference: n8n try/catch + retry + error workflow, LangGraph checkpoint rollback, Dify error handling modes
9
Remove Bot → Agent Edge Restriction
The current block on Bot → Agent edges is unnecessarily restrictive. A Bot summarizing data that feeds into an Agent for action is a valid pattern. The restriction should be removed or replaced with a user-facing warning.
10
Execution History & Replay
Persist per-run execution logs (node I/O, timing, status) to SwiftData. Allow users to inspect past runs, see what each node produced, and replay from a specific point. Essential for debugging complex workflows.
Reference: n8n execution history with per-node I/O, LangGraph checkpoint timeline

P3 — Future (Nice-to-have, advanced patterns)

11
Multi-Port Nodes
Multiple labeled output ports per node, each carrying a different data slice. Mainly useful after Condition/Router node is built (which implicitly has multiple outputs).
12
Swarm / Debate Pattern
Peer-to-peer agent communication with round-based iteration. Very high complexity, niche use case. Could be implemented as a specialized executor type rather than a visual workflow pattern.
13
Trigger System
Schedule-based, webhook-based, or file-watcher triggers to auto-start workflows. Lower priority for a desktop app but relevant for automation use cases.

8. Architecture Decision: DAG vs Cyclic Graph

Approach How Loops Work Who Uses It Complexity Recommendation
Option A: DAG + Loop Nodes Special Loop nodes contain an internal subgraph that repeats. The outer graph stays acyclic. n8n, Dify, Flowise Medium — loop is scoped, easier to reason about Recommended
Option B: Full Cyclic Graph Any edge can loop back. Conditional edges determine when to exit. Max-iteration safety cap. LangGraph High — harder to visualize, risk of infinite loops Power user only
Option C: Hybrid DAG by default + Loop nodes for scoped iteration + optional "advanced mode" for unrestricted cycles Flowise AgentFlow V2 Medium-High — best of both, more UI work Long-term target

Recommendation: Start with Option A (DAG + Loop Nodes). It's what Dify and Flowise use, it's visually intuitive (the loop is an explicit node, not an invisible backward edge), and it keeps the existing cycle detection intact for the outer graph. A Loop node contains a max-iteration cap and an exit condition — the subgraph inside it repeats until the condition is met or the cap is hit.
